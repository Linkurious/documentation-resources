# LK-SEC-2026-3

## Timeline
- 2026-11-11 [Node.js publishes a security release][source] for several HTTPS-related vulnerabilities impacting Linkurious Enterprise.
- 2026-11-13 Linkurious publishes this document acknowledging the impact and remediation steps
<!-- 2026-11-16 Linkurious releases Linkurious Enterprise v4.3.16 fixing the issue -->

## Description
Several vulnerabilities in the TLS and HTTPS modules in Node.js, which is used by Linkurious Enterprise to provide an HTTPS server:
- CVE-2026-123864: A zero-length TLS write re-enters llhttp_execute(), and the server copies its own heap into the request body.
- CVE-2026-126051: Remotely triggerable uncaught exception in TLS servers via deferred handshake callbacks.

## Impact
The TLS/HTTPS module in Node.js allow a remote attacker to expose some internal state of the server and trigger a server crash.
The vulnerability is only reachable when the `server.useHttps` options is set to `true` in the Linkurious Enterprise configuration.

## Severity: high
- CVSS v3.1 score: `7.7` (see [score details][score-details] and [severity rules][severity-rules]).
- Patch highly recommended.
- Workaround available.

## Who is affected?
All versions of Linkurious Enterprise up to v4.3.15 (included) having the `server.useHttps` configuration option set to `true`.

## Workaround
Set `server.useHttps` to `false` in the configuration and use a reverse-proxy to provide HTTPS rather than providing HTTPS
directly from Linkurious Enterprise.

## How can it be patched?
- Upgrade to Linkurious Enterprise v4.3.16 (release date pending confirmation)
